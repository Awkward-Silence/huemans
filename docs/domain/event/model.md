## Bounded Context

Event owns the lifecycle of an event: one night of huemans, which attendees scan into through the QR code. The host creates an event with a name. It starts open, while attendees join and answer, and the host's reveal moves it to revealed. Event announces both moments as its own domain events, and the other contexts listen to them.

It is NOT responsible for:
- the quiz settings (question count and soft timer), which belong to Participation's quiz and are fixed for the MVP;
- the night's icebreaker, which Night Icebreaker picks and stores in its own aggregate when it hears EventRevealed;
- the color distribution, which Color Distribution opens when it hears EventCreated;
- whether attendees can still join or be grouped after the reveal (they can; Event does not stop them).

## Aggregates

| Aggregate Root | Responsibilities | Invariants |
|---|---|---|
| Event | One per event. Owns its id, name and status, and moves from open to revealed | Starts open; is revealed at most once; never goes back to open |

### Event — Detail

**Entities within this aggregate:**
- none

**Invariants:**
- A new event is always open.
- An event is revealed at most once.
- A revealed event never goes back to open.

**Lifecycle events:**
- EventCreated — triggered when the host creates an event
- EventRevealed — triggered when the event moves from open to revealed

**Domain actions:**

| Action | Preconditions | Invariants enforced | Emits |
|---|---|---|---|
| create(SK::EventId id, EventName name) | — | Starts open | EventCreated |
| reveal() | — | Revealed at most once; status only moves open → revealed | EventRevealed (only on the open → revealed transition) |

`create` builds the aggregate. The EventId is generated by this context, as a UUIDv7.

`reveal` is idempotent. On an event that is already revealed it succeeds, changes nothing and emits nothing, so a double tap by the host is harmless.

There is no rename, cancel or reopen for the MVP.

| EventStatus | basic | string | One of: open, revealed | any other value | Local |

### EventName — Detail

**Construction rule:** the given text with surrounding whitespace removed. It must hold at least 1 and at most 255 characters after trimming. Two events may share a name, because their EventIds tell them apart.
**Immutable:** yes
**Equality:** by value

## Domain Events

Published by Event and owned by this context, not by the shared kernel. Consumers subscribe to them through synchronous in-process handlers, which run to completion before the triggering request returns. There is no queue or background job.

| Event | Trigger | Aggregate | Payload | Status |
|---|---|---|---|---|
| EventCreated | create | Event | eventId: SK::EventId | Active |
| EventRevealed | reveal, only on the open → revealed transition | Event | eventId: SK::EventId | Active |

Known consumers:
- Color Distribution consumes EventCreated and opens the event's distribution.
- Night Icebreaker consumes EventRevealed and picks the night's icebreaker.

## Ubiquitous Language

| Term | Definition |
|---|---|
| Event | One night of huemans: what attendees scan into through the QR code. It has a name and a status |
| Host | The person who creates the event and taps "reveal" on the big screen |
| Event status | Where the event is in its lifecycle: open while attendees join and answer, then revealed once the host has revealed the night |
| Reveal | The host's single action that ends the open phase. Other contexts react to it, and the night's icebreaker is picked by Night Icebreaker, not here |
| Quiz settings | The number of questions and the length of the soft timer. Fixed for the MVP (5 questions, 20 s) and owned by Participation, not by Event |

## Open Questions

- Per-event quiz settings are deferred. If they come back, they belong to Participation's quiz, not to Event.
- In code, `EventCreated` sits in the shared kernel folder. It has to move into the Event context, and its consumers have to import it from there.
