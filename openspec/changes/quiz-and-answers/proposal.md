# Proposal

## Why

Join and the quiz are the last parts of the attendee flow that `web/` still fakes in `http` mode: `web/src/api/index.ts` keeps the in-browser mock for `join` and `getQuiz`, so the attendee id is made up on the phone and every event shows the web's fixed question list. Submitting answers already reaches `api/` (Participation scores them and Color Distribution groups the attendee), but anyone can submit for any made-up id, and the room's `total` is a stub that equals `answered`. With real join and quiz endpoints the whole demo runs on the backend, and the room can show who joined but hasn't answered yet.

## What Changes

- Participation records attendees. `POST /events/:eventId/attendees` joins with a name only and returns `201 { attendeeId }` (UUIDv7, generated by the attendee). Every call creates a new attendee, and joining stays open after the reveal. The name is trimmed and must be 1-40 characters.
- `GET /events/:eventId/quiz` returns the event's 5 questions and the 20 s soft timer (`durationSeconds`). They are picked deterministically from the event id, so every phone gets the same questions in the same order with nothing stored, and they come from as many different themes as possible. Answers are served without their trait.
- **BREAKING** (for API clients only, `web/` already joins first): submitting answers requires an attendee who joined that event. An unknown attendee, or one who joined another event, is a `404`. The rest of submit is unchanged: soft timer, unknown ids ignored, a second submit returns the first group.
- `QuestionnaireCompleted` moves from the shared kernel folder into Participation, which publishes it. Color Distribution and Night Icebreaker import it from there.
- The quiz settings (5 questions, 20 s) become Participation's. `GET /events/:eventId`, `POST /events` and the reveal read them from Participation instead of the placeholder constants in `EventController`.
- The room's `total` counts the attendees who joined the event (from Participation), replacing the "everyone who answered joined" stub.
- `web/` in `http` mode stops mocking `join` and `getQuiz`. Until `word-suggestions` serves the quiz's `sentence` field, the web keeps the mock's sentence question, so the "I ..." step doesn't disappear.

### New Capabilities
- `participation`: joining an event with a name, serving the event's quiz, submitting answers with a soft timer, and the attendee counts the room reads.

## Impact

- `api/src/Participation`: an `Attendee` aggregate with its repository and migration (`attendees` table), the quiz picked in the domain, two new endpoints, and the attendee check in `submit`.
- `api/src/Shared/Domain/Event/QuestionnaireCompleted.ts` moves to `api/src/Participation/Domain/`; the subscribers in Color Distribution and Night Icebreaker change their import.
- Event (`EventController`) and Room (`JoinedAttendeeCounter` adapter) read from Participation's `ApplicationService`.
- Functional tests that submit answers for a made-up attendee (Participation, Night Icebreaker) join first. So does `pnpm test:e2e`.
- `contracts/participation.d.ts` gains the join and quiz types; `docs/api/attendee-api.md` endpoints 2-4 and 6 are updated.
- `web/src/api/index.ts` drops the `join` and `getQuiz` mock overrides.
- `word-suggestions` task 5.2 then adds `sentence` to the quiz endpoint this change creates.
- Depends on `create-event` and `catalog-aggregates` (both applied). Owner: Diego.
