# Proposal

## Why

Once someone scans the QR code, they join with a name, answer 4-5 funny questions and wait for their color. That is the Participation side of the walking skeleton. Color Distribution already assigns groups on `QuestionnaireCompleted`, so the only missing link between the phone and the reveal is a context that serves the quiz, records the answers and turns them into a trait profile.

## What Changes

- Add a Participation bounded context in `api/src/Participation/`.
- `GET /events/:eventId/quiz` returns the event's questions. They are picked deterministically from the `eventId` and the event's `questionCount`, so every phone gets the same questions in the same order with nothing stored. Prefer varied themes. Answers never expose their trait.
- `POST /events/:eventId/attendees` joins with a name only and returns `{ attendeeId }` (UUIDv7, generated by the aggregate). Every call creates a new attendee. Joining stays open after the icebreaker reveal.
- `POST /events/:eventId/attendees/:attendeeId/answers` accepts `{ answers[], elapsedMs }`:
  - The timer is soft: late submissions are accepted, and `elapsedMs` is stored for fun stats.
  - Each `answerId` maps to its trait through the catalog. Unknown question or answer ids are ignored.
  - The resulting trait profile is published as `QuestionnaireCompleted { eventId, attendeeId, traits }`, which already exists in the shared kernel.
  - A second submission is a no-op, because assignments are final.
- Unknown event or attendee → `404`. The event is looked up through the Event context.
- Expose per-event counts (attendees joined, attendees who answered) for the `/room` read model in `web-live-distribution`.
- The request and response shapes are endpoints 2-4 in `docs/api/attendee-api.md`, which `web/` already codes against.

## Capabilities

### New Capabilities
- `participation`: joining an event with a name, serving the event's quiz, submitting answers with a soft timer, and the resulting trait profile.

## Impact

- New `Participation` module in `api/`, with its migration.
- Reads questions and their traits from Catalog (`backend-skeleton-and-catalog`). Until that lands, a provisional adapter can read the `tools/` question list already parked in `api/src/Catalog/Infrastructure/Content/`.
- Depends on `create-event` for event lookup and quiz settings. It can start against a stub lookup.
- `word-suggestions` adds an optional `sentence` field to the quiz response.
